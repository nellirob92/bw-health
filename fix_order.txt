# Fix order for the report: which logins to fix first.
#
# One entry per line. A line that starts with # is a note.
#
#   <tier> <domain>          a site, and every address under it: "1 google.com" also covers
#                            accounts.google.com, but not google.example.com
#   <tier> .<ending>         every address ending in it: "1 .gov" covers ssa.gov and irs.gov.
#                            A domain line wins over an ending line.
#   <tier> folder: <name>    every login kept in a Bitwarden folder with exactly this name
#                            (capitals do not matter). A folder line wins over the others.
#
# This file is the one place the kinds of site are decided; the report names each tier.
#
# The two-step login check uses the domain lines too. A login whose address sits under a domain
# listed here is compared with the public 2FA Directory list as that whole site, so
# accounts.google.com is compared as google.com. In the report a match made that way reads
# "likely supports two-step"; only an address that is on the list itself reads
# "supports two-step". Adding a domain here can therefore add "likely" matches for that
# site's other addresses.
#
# Tiers:
#   1  email, and Apple, Google and Microsoft accounts (they reset every other password), and
#      identity: every .gov site, login.gov and id.me (they prove who you are)
#   2  money: banks, cards, brokerages, payment apps, Amazon, PayPal, tax software
#   3  phone carrier, utilities, insurance, health portals
#   4  gaming and social
#   5  everything else (any site not listed here)
